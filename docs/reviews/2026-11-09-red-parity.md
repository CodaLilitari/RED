# RED parity review — 2026-11-09

RED includes the inspected upstream C++ editor revision and substantial SED-MotS port work. This review repaired reproducible preservation, geometry, KEY and headless transaction defects, and expanded bounded level-authoring operations. It does **not** establish complete old-editor feature parity, a qualified release package, or actual-game acceptance.

## Source and scope

- RED baseline: `cc0b5b8193fe2d14e818056260534bb7fe7078c1` on `red/main`.
- Upstream comparison: `smlu/SED` `develop` at `b82255998fb733c8e8c87104eb7c17f27b48376f`. The coordinating ancestry check recorded this revision as fully incorporated, with zero missing commits. No unmerged upstream feature is inferred from an older checklist.

- Reference scope: current RED sources, the existing SED-MotS-Consolidated protocol/source, and the OpenMotS KEY reader. Source inspection, synthetic execution, native application behavior and actual game behavior remain distinct evidence levels.

The [capability matrix](../capability_matrix.md) and [gap register](../gap_register.md) are the living ledgers. Private paths, game assets, account receipts and reviewer session identifiers are deliberately kept in the coordinator's external evidence store.

## Remaining parity and acceptance work

- **Old headless protocol:** exact array aliases/field contracts, ARCH bind/rebind/bake, free vertex editing, dedicated texture fit/align, and complete strict JSON Schemas remain open. Generic plan/apply still accepts omitted `schemaVersion`, `inputSha256` and `sourceRevision`; the documented workflow supplies them. Matching command names do not imply protocol equivalence.
- **Migration and preservation:** `.sed` dispatch still assumes the binary container; legacy text SED signature routing and companion-template revision capture remain gaps. JED/NED variants and unknown engine records need fixture-specific comparison. Native opaque-state refusal is deliberate protection, not complete workspace editing support.
- **Resource/render workflow:** dependency traversal covers several additional asset kinds, but AI-class closure and runtime package closure remain unverified. `software-v1` snapshots contain world surfaces only. Full GUI archive/package/launch workflow, independent RGB controls and model-inclusive snapshots remain incomplete.
- **Editor/product scope:** general model/hierarchy/animation authoring, loss-aware project conversion, whole-level diagnostic overlays, numeric camera fields, historical developer/ISED/plugin acceptance, and shadow-driven subdivision remain separate work. Prefab text I/O, statistics, masked recipes, terrain-model export and emission/bounce/sky code already exist; they should not be listed as wholly absent.
- **Platform and game acceptance:** the final Windows native gate, fresh package/launch, full Linux/macOS editor validation and representative JKDF2/MotS/IJIM/DroidWorks edit-save-visual-gameplay lanes are not closed here. COG preflight is not a compiler. Engine loading, player activation, path motion, objectives and negative controls require actual causal runtime observations. DroidWorks remains a partial profile.

The final native follow-up also repaired missing grouped resource-tab icons using public Qt APIs, with ambiguity and foreign-tab nonmutation checks. DPR-normalized gesture fixtures, documented shortcut/menu expectations, topology-mode fixtures and scoped locale restoration have focused passing evidence. The remaining clipboard/ARCH failures and default-scale fixture limits stay open in the handoff.

No historical core-only total, source inspection, reviewer response or editor image replaces those acceptance gates.
