# RED product roadmap

These are approved product directions for the standalone editor. Each identifier names a reviewable piece of work. Detailed behavior below is a proposed implementation contract until its acceptance evidence exists. The [designer guide](user_guide.md) describes available workflows. Source evidence identifies the starting point on the branch. Distribution and qualification belong to individual releases.

**Existing** means a named behavior has an implementation. **Partial** means a delivery item extends a working subset. **Planned** means its acceptance workflow remains to be built. **Experimental** means approval covers investigation with an explicit decision gate. Labels describe the whole ticket. A starting point can be existing while the next operation is planned.

## Order of work

| Lane | First deliverable | What it unlocks |
| --- | --- | --- |
| Native assets | MESH-01 source document, then MESH-02 checked writer | Fixed-topology authoring, KEY fitting and safe asset publication before topology changes. |
| Renderer evidence, in parallel | REND-01 indexed snapshot and LAB-01 calibration fixtures | Reproducible material diagnostics, separate renderer comparisons and measurable bake quality. |
| Reliability throughout | REL-01 failure, recovery and performance baselines | A gate for every new mutation, release and target claim. |
| Model and lighting production | MESH-03 through MESH-07, LIGHT-01 through LIGHT-05 | Native variant production and budgeted offline lighting outputs. |
| Review and projects | ID-01, REVIEW-01, VALID-01, LOOP-01 and the project tickets | Reviewed multi-author changes and a continuous path from level edit to captured package. |
| Ecosystem | ASM-01, EXT-01, LIB-01 | Reusable content and third-party operations with explicit ownership, licensing and recovery. |

A lane can develop against an owned synthetic fixture while another lane is in progress. A dependency gates promotion of the dependent workflow. It need not block preliminary interface or fixture work. Keep project additions optional for loose-file editing. Exports must remain readable by the selected target using its ordinary formats. GeoSith is a complementary in-engine editor in the [comparison](editor_comparison.md). Integration and shared live co-editing with it are outside this roadmap.

## Native assets and reliability

**MESH-01 through MESH-06 · Native 3DO and KEY studio · Partial.** RED already imports OBJ/GLB, edits hierarchy and pivots, previews and edits KEYs, and relights ordinary models. Its rendering representation exposes a selected geoset and can expand instances. Native authoring therefore starts by admitting supported raw 3DO 2.1 documents with checked spans and identities for every geoset, shared mesh and joint. MESH-01 must round-trip a no-op byte for byte and reject ambiguous editable data. MESH-02 must preserve every unrelated source byte after a supported fixed-topology change. A second reader must agree on the intended result. Existing behavior and the complete per-ticket fixture matrix are in the [model design](native_mesh_editing_proposal.md) and [current model representation](../src/core/include/sed/assets/3do.hpp).

MESH-03 adds deterministic edits and one undo record per interaction. MESH-04 adds selection, gizmos, numerical editing and KEY preview in the native studio. MESH-05 adds reviewed automation, source-hash checks, create-only publication and recovery. MESH-06 closes the first production slice when a mapper can edit a shared-mesh variant, inspect affected instances and sampled poses, cancel or undo exactly, recover a draft and publish it into a named target package. A successful writer test alone cannot close this ticket.

The [portable document and source writer](native_model_document.md) retain all LODs and source-mesh identities while
changing admitted UV components or whole-mesh positions through positive uniform scale and translation. The
[reviewed CLI/MCP workflow](native_model_authoring.md) adds paged address inspection, before/after reports, source and
request/output hash checks, and atomic create-only publication. Normals, authored radii, hierarchy and stored lighting
remain unchanged; geometry changes require lighting and radius review. Tests cover shared/orphan meshes, numeric and
byte preservation, malformed input, bounded work, review mismatches and publication failures. The
[portable session](native_model_session.md) adds source-addressed selection, transactional proposals, bounded exact
source history and session-bound clean checkpoints for these existing edits. Model Studio interaction, individual
vertex deformation, rotation, normal/face/radius editing, history integration and recovery remain open.

**MESH-07 · Topology and budget-aware partitioning · Planned.** Depends on MESH-06 and a reviewed rewrite/remap contract. Preserve or explicitly remap independent position, UV, normal, mesh and joint identities across topology changes. Show inherited face attributes, LOD scope, loader limits and effects on attached KEYs and ARCH data before publication. Acceptance includes seams, reflected winding, shared instances and sparse animation tracks. Show observed draw-size warnings separately from loader rejection. Record which animation poses and engine configurations were exercised.

**MESH-08 · Complete the content studio · Planned.** After the fixed-topology milestone, extend face assignment and UV editing to multi-face unwrap and island operations, then use MESH-07 remapping for LOD generation. Compare source and generated LODs in motion, inspect visual versus collision bounds, and trace PUP animation associations. Retarget KEYs only across explicitly mapped compatible hierarchies. Refuse ambiguous joints and show the sampled poses used to judge a fit. Test a Blender-Sith round trip with independent readback and fit an owned Tripo-generated prop or armor piece to a known attachment. Report changes to scale, pivots, UVs, materials, binding and budgets before accepting a generated variant.

**REL-01 · Reliability, performance and release qualification · Partial.** History, autosave recovery, staged publication, release-layout checks and hot-path tests already exist. Extend them with each new document type and operation. Record a baseline corpus, workload, platform, elapsed time and allocation or memory budget before accepting a performance threshold. Verify cancellation, stale inputs, failed writes, concurrent creation, exact undo/redo, recovery after interruption and reopening older workspace data. Keep failed output unpublished. Exercise the packaged executable on each platform claimed, including resource discovery and opening a project. Report exact commands and outstanding native desktop or engine gates. The full Release CTest gate is defined in [AGENTS.md](../AGENTS.md). Existing coverage includes [document recovery](../src/app/tests/document_recovery_tests.cpp) and [frame rendering](../src/app/tests/frame_render_performance_tests.cpp).

Include filename integrity in this gate. Audit CLI, MCP and Qt boundaries one workflow at a time with Unicode source,
resource, workspace, temporary, package and recovery paths. Compare every successful reported output with its native
filesystem entry and verify containment on case-sensitive as well as case-insensitive roots. The
[native authoring contract](native_model_authoring_design.md#filesystem-paths) defines this for its three commands;
that coverage does not establish Unicode support for all other command families.

The [selected level workflows](agent_workflow.md) now preserve native Windows filenames through CLI `inspect`,
`new`, `query`, `select`, `validate`, `plan` and `apply`, and their MCP routes. Their regression coverage uses real
`CreateProcessW` calls and UTF-8 stdio with ASCII, accented, CJK and astral names, distinct mojibake source twins,
Unicode request/workspace/temporary paths, occupied destinations and journal replay. Apply prepares its UTF-8 receipt
before publishing to the same native destination. Executable-adjacent template discovery retains the native executable
path. A historical completed operation still returns its recorded receipt; an upgrade does not re-execute old writes.

Continue the filename audit across other legacy command families and nested resource host paths. Carry the same
source-hash, native-entry, valid-receipt, confinement and replay checks into each bounded batch. Keep filesystem path
decoding separate from archive-entry names, authored game/resource identifiers and byte-preserving dependency
diagnostics. The implemented level-route coverage does not qualify those remaining boundaries or replace the complete
Release and packaged-installation gates.

## Renderer evidence and lighting

**REND-01 · Indexed snapshot profile · Partial.** The separately selectable [indexed JK world profile](lighting.md#jk-indexed-world-snapshots) implements cel zero, mip zero, nearest sampling, opaque and keyed surfaces, and separate Solid and Textured paths. It retains original MAT indices, follows the cel's texture selector and translates indexed light through the owning sector's CMP before resolving the master palette. Rendered snapshot and overview receipts identify the applied profile, geometry scope, light source and hashed resources. Unsupported or incomplete inputs refuse before PNG publication. Automation must verify the returned profile because older clients or binaries may ignore unknown fields. The default software snapshot remains the comparison baseline.

Accept against equal-RGB indices with distinct ramps, a nonmonotonic table, two sector CMPs, original key zero versus a mapped zero, and separate palette fullbright and FULLYLIT face cases. Keep default snapshot output stable. Qualify mip selection, static Things with owner-sector tables and optional transparency tables separately before advertising them. An RGBA PNG can carry the resulting pixels. The contract applies to the sampling calculation, independently of the PNG encoding.

**LAB-01 · Lighting Lab and renderer comparisons · Planned.** Alongside REND-01, build a distributable synthetic room with owned MAT/CMP/model assets, fixed viewpoints and documented illumination. Capture indexed software, 16-bit hardware and the exact engine modes available. Record executable/build, game, renderer, package and resource identities, camera, settings, and capture method. Preserve discrepancies in interpolation, mip choice, clipping or tint as measured differences. Keep RED's viewport, deterministic snapshot, OpenJKDF2 reconstruction and retail observations individually labeled. Add spatial overlays for visibility, overdraw, culling, collision bounds, sound reach and camera frusta. Label geometry estimates separately from measured renderer counters. A hardware editor preview alone cannot certify a retail renderer. Expose overlays for selected CMP/light row, mip, emission, visibility, normals, direct and bounced light, interpolation error and added cost as their underlying data becomes available. Acceptance requires tracing one visible discrepancy back to the relevant surface, material and target receipt. [Capture workflow](game_testing.md)

**LIGHT-01 · Material-aware scene bake · Partial.** World ray baking, saved recipes, shadow cuts, model relighting and MotS ARCH authoring have independent implementations. Static blockers alone do not provide a common material-bearing scene. After LAB-01, build immutable primitives with source, sector, material/UV, emission, occlusion and receiver identities. Start with admitted static opaque geometry. Compare the same slab as world geometry and a placed model, a pedestal casting onto a world floor, and two placements needing different results. Changing a placement must invalidate the recipe. Preserve originals and deduplicate equivalent generated variants. Ordinary classic 3DO 2.1 output is scalar in both games. Distinguish JK world scalar, MotS world RGB and eligible per-Thing MotS ARCH output. Inspect additive model light with sector ambient and face settings. Benchmark CPU and GPU offline baking on the same admitted scene, sample budget and documented hardware. Report elapsed time, transfer/setup cost, peak memory and output differences against a stated tolerance. This benchmarks authoring time. [Lighting contract](lighting.md) · [Model lighting](model_lighting.md)

**LIGHT-02 · Adaptive lighting-error cuts · Planned.** Depends on LIGHT-01 and LAB-01. Compare an interior light sample with the target's corner interpolation, then rank refinements by measured reduction in error per added primitive. Holocron documents the loss of interior detail and wall cutting. RED already has owned Shadow Cuts. Acceptance requires a heatmap, before/after error on held-out samples, explicit corner/surface budgets, stable adjoins and reversible regeneration on the same scene. Treat world and mesh refinement as separate operations. [Holocron comparison](editor_comparison.md#holocron) · [Shadow cut tests](../src/core/tests/level/shadow_cuts_tests.cpp)

**LIGHT-03 · Bake to MAT and optimize lit palettes · Planned.** Depends on LIGHT-01, REND-01 and LAB-01. Compare a surface-specific standard MAT against retaining corner lighting or adding geometry. Preview texture bytes, residency pressure, cutout edges, mip seams and static-light limitations. For indexed assets, optimize palette slots across the levels of light actually used, protecting reserved, keyed and fullbright entries. Accept only with a reviewed output family, measured errors across several light rows and mip levels, and unchanged unrelated assets. Preserve both 8-bit and RGB565 editions where explicitly requested. [Material authoring](material_authoring.md)

**LIGHT-04 · Source rigs, emission masks and finite lighting states · Planned.** Depends on LIGHT-01 and reviewed generated outputs. Store offline area/emissive source definitions and masks in editor-owned metadata. Show how each contribution maps to an ordinary target representation. Compile a finite state example through qualified COG light or cel changes and eligible target-specific vertex changes. Demonstrate deterministic regeneration and undo, startup, transition, save/reload and multiplayer behavior for each state claimed. Report script and resource costs alongside the static result. [Lighting](lighting.md) · [Runtime lighting switch tests](../src/app/tests/runtime_lighting_switch_tests.cpp)

**LIGHT-05 · Solve toward an authored look · Experimental.** Depends on REND-01, LAB-01 and explicit LIGHT-01/03 output budgets. Given reference samples and allowed variables, compare a bounded inverse-lighting fit with a hand-authored baseline. Report residuals, held-out view error, resource costs and ambiguity. Retain the original authoring source. Advance only if the fit reproduces on a second fixture, improves the named metric and produces inspectable standard outputs.

## Review, validation and target testing

**ID-01 · Stable identities and semantic merge · Partial.** RED's [semantic previews](semantic_preview_design.md) describe addresses within a particular snapshot. Independent renumbering can invalidate index-only matches. Define optional persistent editor identities and rules for copy, split, merge, deletion and remap. Preserve ordinary runtime indices at export. A three-way comparison must merge disjoint changes deterministically, explain an edit/delete conflict, and refuse ambiguous legacy matches without mutating the document. Test two agents starting at one baseline and two branches performing unrelated reordering. Support cherry-picking a room or assembly with its required references, previewing the closure before applying it. Provide per-author and session summaries from recorded edit provenance, marking unknown authorship explicitly. Include explicit unsupported domains and a way to inspect the base and both candidates.

**REVIEW-01 · In-GUI semantic review · Partial.** The [reviewed material edit](../src/app/src/ui/project/reviewed_material_edit.cpp) already applies a scoped surface assignment with undo. Extend plan review one operation family at a time. For geometry, resources and generated files, identify what will change, show spatial or typed before/after evidence, expose omitted scopes and link each change to its owner. Depend on ID-01 for cross-revision matching. Require the same checked plan through GUI and automation, stale-baseline refusal, exact cancellation and one undo transaction. Overlay ghosted before/after geometry with a selectable source entity. Accepting a coherent subset must create and validate a new plan with its dependencies before applying it. Verify that a user's unrelated unsaved draft survives acceptance and rejection.

**VALID-01 · Corrective validator · Partial.** Build on existing [validation](headless_validation.md), [surface flag repair](../src/core/src/level/surface_flag_repair.cpp) and reviewed adjoin work. Return location, affected entity, target, observed value, applicable limit and an explicit repair where deterministic. Prioritize resource resolution, radius/bounds discrepancies, broken references and seams. Show the proposed change and its downstream effects before commit. A synthetic broken scene must lead from finding to selection to reviewed correction, revalidate cleanly for that finding and reproduce the original diagnostic after undo. Distinguish engine limits, observed draw pressure and estimates. Ambiguous repair remains a finding.

**LOOP-01 · Edit, validate, package, run, capture and compare · Partial.** RED already stages levels, launches configured engines and supports project scenarios and external capture helpers. Bring those steps together around one named scenario, including a configurable fast-play shortcut in the spirit of Holocron's F5. Bind each result to the exact saved input, ordered resource identities, package and selected executable. Support direct navigation from a diagnostic or comparison back to the source. Repeating after one visible edit must produce distinct identified results and comparable views. Missing captures, skipped checks, launch failure and menu-only startup must remain distinguishable from a completed scenario. Test retail JK, retail MotS and OpenJKDF2 profiles separately. Extend scenarios with named start positions, routes and recorded input macros. Compare matched frames and performance samples, identifying any route or timing divergence. Preserve and restore the editor camera across runs. Advertise engine camera restoration or hot reload only for configurations with demonstrated support. A passing OpenJKDF2 run qualifies only that executable and configuration. [Engine staging and receipts](game_testing.md) · [Capture helpers](../tools/engine-capture/README.md)

**COG-01 · Compiler and debugger integration · Partial.** The [compiler](../src/core/src/assets/cog_compiler.cpp), [scoped simulator](cog_runtime.md) and [assistant trace review](../src/app/src/ui/assistants/cog_trace_review.cpp) supply separate pieces. Connect source diagnostics to spans and bound level/resource values. Retain the linked external COG's path and dirty-buffer identity when navigating between instances. Add breakpoints, stepping, watches and message history for supported simulation semantics. Require a reproducible fixture showing two instances with different bindings, a failing handler, source navigation and deterministic replay. Cross-navigate a bound Thing or surface between source and viewport. Step to the next message or scheduled timer and display the issuing instance, receiver, simulation time and changed values. Unsupported verbs must surface explicitly. Compare an instrumented target trace under LOOP-01 before labeling a behavior engine-observed.

## Projects, components and extensions

**PROJ-01 · Project Cockpit and campaign production · Partial.** The [cockpit](../src/app/src/ui/project/project_cockpit.cpp) and [portable profiles](portable_projects.md) already cover mounts, progression and multi-level packaging. Extend the cockpit into an actionable campaign overview with per-level entry/exit links, dependency and validation results, build status, test receipts and navigation to the responsible source. Include campaign-wide state, cutscene transitions and shared script, template and asset libraries. Exercise one persistent objective across a level transition and one shared-library change affecting two levels. Depend on LOOP-01 for verified runs. In a two-level fixture, relocate the project, change a shared input and identify which results became stale. Navigate to the affected level, rebuild the episode, exercise progression on the chosen engine and associate the receipt with that exact episode.

**ASSET-01 · Visual asset browser and complete family placement · Partial.** The [family resolver](../src/project/resource_families.cpp), [browser](../src/app/src/ui/project/resource_family_browser.cpp) and [dependency inspector](dependency_inspection_design.md) already expose typed content, mount winners, shadowing and reviewed insertion. Join visual search, dependency and reverse-use navigation with placement-time diagnostics. Before committing, show whether the model/material/KEY/COG/sound dependencies required by the selected family resolve, where each came from and how the placed material responds to the destination sector palette. The preview matrix should cover MAT animation, mips, transparency and fullbright response, 3DO LODs, KEY playback, COG symbols and references, WAV playback and SND mappings, SPR frames, CMP ramps and expanded templates with inherited values. For each type, test a valid sample and a missing or malformed dependency. Depend on REND-01 for an indexed appearance claim. Test missing and shadowed inputs, conflicting names and palette mismatch. Resolve or decline the preview without partial insertion. Report bounded graph coverage explicitly.

**JED-01 · JED/NJED comfort layer · Partial.** Preserve the existing [workspace preset](../src/app/tests/jed_workspace_tests.cpp), command search and editing behaviors, including tested [partial-overlap Connect](../src/core/tests/level/level_connect_contract_tests.cpp). Review shortcut discoverability, selection, grid commands and fast play against a matched scenario. Have designers align and connect a doorway, wire a switch and launch it with keyboard navigation. Record task completion, misfires, recovery and discoverability for both default and compatibility profiles. Check focus in text editors and conflicts with custom shortcuts. Use the observed failures to choose changes.

**ASM-01 · Smart Assemblies · Planned.** [Prefabs](../src/core/src/level/prefab.cpp) and [gameplay assistants](gameplay_assistants.md) already produce reusable level content. Retain optional assembly identity, parameters, generated-member ownership and overrides in editor metadata. Depend on ID-01 and REVIEW-01 for reliable regeneration. Use a door, lift or switch as the first fixture. Edit a parameter, preview the impact on geometry, Things and COG bindings, preserve a supported local override, then undo. Detect a deleted or ambiguously edited member. Detach into ordinary editable elements. Export and run the fixture with standard target resources and verify that no runtime assembly metadata is required.

**EXT-01 · Safe transactional extensions · Partial.** Preserve the existing [IJED-compatible host](../src/core/src/plugins/jed_plugin_host.cpp) and the documented [plug-in patch contracts](plugin_patches.md). Define a portable, versioned extension request with declared capabilities, bounded input/output and typed edits subject to the core validator. Separate trust and execution policies for legacy native code and new external workers. Start with a read-only inspector and one reversible operation. Across each supported platform, test timeout, crash, incompatible version, invalid output, unauthorized file access and stale document revision. Require explicit trust scope, unchanged document on rejection and one undo on acceptance before advertising the new extension path.

**EXT-02 · Extension package browser · Planned.** Depends on EXT-01. Show publisher, source/provenance, license, supported games, supported RED/API versions, test evidence and requested capabilities. Verify package identity and signatures against the declared trust policy before installation. Show unsigned, unknown-signer, invalid-signature and incompatible packages distinctly. Exercise install, update, rollback and removal without losing a project's pinned versions.

**LIB-01 · Curated RED component library · Partial.** RED already ships [COG templates](cog_templates.md) and gameplay assistants. Package owned or redistributable components with preview, parameters, provenance/license, game target, dependencies, tested limits and example usage. Depend on ASSET-01 and ASM-01 for reviewed parameterized placement. Ship a small representative set first, for example a wired door, reusable objective and animated prop. Broader catalog candidates include vehicles, mounted creatures, objectives and cutscenes, multiplayer systems, architecture and material kits, and Shadows of the Empire-style space mission frameworks. Qualify each for its own target, license and runtime dependencies. A fresh project must discover each component, preview the complete resource family, detect collisions and insert it transactionally. Reopen, validate, package and run a representative result. Preserve compatibility or document migration when a component version changes.

## Closing a ticket

Record the reviewed change, reproducible fixture, exact entry points, negative cases and evidence for each target claimed. A core-only pass, native GUI pass, package inspection and observed retail run answer different questions. Keep unresolved target and renderer combinations visible. Update the owning designer and format contracts when behavior lands, then advance the status here. Historical provenance and tool comparisons belong in the [comparison guide](editor_comparison.md).
