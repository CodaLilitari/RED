# RED implementation and evidence gap register

This register tracks implementation and acceptance work for the JKDF2, MotS, IJIM, and DroidWorks editor. Stable IDs match [the capability matrix](capability_matrix.md). It is an engineering ledger, not a completion claim.

Unless a row explicitly says **observed**, its implementation statement is inherited from the capability matrix and is **unverified in this checkout**. Historical tests, screenshots, package counts, and reference-engine behavior are not current acceptance. “Owner” names the implementation and acceptance roles; Andrei owns any waiver and actual-game sign-off. Private game paths, hashes, and runtime observations remain outside the repository.

Every lane ultimately requires a controlled edit, save/reopen and semantic/unknown-data comparison, followed by visual and actual-game checks where applicable. A synthetic structural test alone never closes an A-row.

**Observed configured validation:** the established full-tree build and test examples are `cmake --build build/ninja --config Release --parallel 4` and `ctest --test-dir build/ninja -C Release --output-on-failure -j 1`. For the current Planarize change in the existing `SED_BUILD_APP=OFF` MSVC tree, `VsDevCmd.bat -arch=x64 -host_arch=x64` established the compiler environment and `cmake --build build/ninja --config Release --target sed_core_tests --parallel 1` completed the current core test target. `ctest --test-dir build/ninja -C Release --output-on-failure` passed **88/88 entries in 28.95 seconds**, including 20 agent CLI and five MCP stdio scenarios. Before the Planarize fix, `sed_core_tests.exe --recipe-operations` exited 1 with three expected assertions: a planar no-op was reported as changed, and direct/batch malformed trailing references left earlier vertices moved. The focused group and full suite passed after the fix. The earlier agent scenario first failed with `unsupported operation 'setThingFrames'`; the earlier ARCH preview scenario also had recorded red source-ordinal/preview assertions before its fix. These runs supply structural evidence only for the configured core, allocation, agent/MCP, updater, native-inspection and synthetic-capture coverage. A row's statement that its own fresh acceptance was not run still stands where it requires Qt, native UI, real resources, packages, render comparisons or target games; this core-only run is not the default Qt Release gate.
