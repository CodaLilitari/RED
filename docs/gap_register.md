# RED implementation and evidence gap register

This register tracks implementation and acceptance work for the JKDF2, MotS, IJIM, and DroidWorks editor. Stable IDs match [the capability matrix](capability_matrix.md). It is an engineering ledger, not a completion claim.

Rows distinguish **source-inspected** contracts, **existing coverage** and missing acceptance. Existing tests and historical observations are not a fresh pass for the final source. Stable IDs match the capability matrix; the [source review report](reviews/2026-11-09-red-parity.md) records the pinned baseline/upstream comparison, reproduced defects and bounded reviewer scope. Andrei owns explicit waivers and actual-game sign-off; none is inferred from a missing test environment.

At the earlier Qt checkpoint, a default Qt Release build and all 50 core/agent/MCP checks passed. The complete default-scale gate returned **184/199 passed, 15 failed** before the last native repairs; no successful full final-source gate is recorded. Later focused checks cover the repaired native fixtures and grouped-tab icons, while clipboard/ARCH failures and display-scale limits remain open. See [the continuation handoff](reviews/2026-11-09-red-handoff.md) for exact results. A standalone Linux/POSIX publication check is narrow primitive evidence, not full editor/platform or game acceptance.

The subsequent [agent parity review](reviews/agent_parity.md) records the reconstructed source, shared schema/CLI/MCP inventories, focused refusal and preservation regressions, and that slice's Linux headless Release gate. That pass does not close the earlier Qt failures or any visual/game acceptance lane.

The [dependency inspection contract](dependency_inspection_design.md) and [review record](reviews/dependency_inspection.md)
track the inspect-only graph slice, including physical archive provenance, shared package-reader compatibility and
independent traversal/detail bounds. Runtime closure and dependency-complete prefabs remain separate gaps.

Every game lane requires a controlled edit, save/reopen and semantic/unknown-data comparison, followed by visual and causal actual-game checks. Private paths, game hashes, account/session receipts and runtime logs remain outside the repository.
